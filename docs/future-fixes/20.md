# Audit finding 20: Expired stale reservations are not advertised as active

Validated against main `44c2b04`, 2026-10-30. Implemented on `future-fixes`.

## Confirmed problem

A reserved link past its reservation timeout was shown as active without checking its own expiration. The actual pay endpoint already rejected the expired link.

## Change

After an elapsed reservation, derive public status from expiresAt before returning active. Preserve processing for an owned in-flight reservation, and paid/canceled final states. This fixes the read/checkout state only; it is not an expiry bypass repair.

## Verification

node --import tsx scripts/future-fixes/20.verify.mjs covers expired and live stale reservations, in-flight processing, and paid history.

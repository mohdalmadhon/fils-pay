# Audit finding 11: Reporting passes serialize across processes

Validated against main `44c2b04`, 2026-10-30. Implemented on `future-fixes`.

## Confirmed problem

The process-local running flag does not protect the catch-up CLI or another replica. Both can read the same cursor and add the same event to rollups.

## Change

readCursor acquires FOR UPDATE for the transaction. CLI rebuild now takes that lock before rollup locks, in worker order, to avoid deadlock. No migration; historical double counts require a reviewed reporting rebuild after all workers are upgraded.

## Verification

node --import tsx scripts/future-fixes/11.verify.mjs uses two actual PostgreSQL transactions in an isolated schema: the second reader blocks, then sees the first committed watermark.

# Audit finding 07: Cache counts payable when ledger legs are posted

Validated against main `44c2b04`, 2026-10-30. Implemented on `future-fixes`.

## Confirmed problem

Capture credits the payable ledger, rebuild copies that credit, and close previously added it a second time. A real capture/rebuild/close/pay lifecycle reproduces the drift.

## Change

Capture and negotiated-discount postings now apply matching cache deltas in their own ledger transactions. Closing only updates batch metadata; a missing cache row initializes from the ledger. Existing cache-only display corrections are preserved during normal increments. Deploy API and settlement together while captures/closes are paused, then perform one reviewed CLI rebuild to clear historical drift; a rebuild also clears display-only adjustments under ADR 0006. No ledger or historical batch is rewritten.

## Verification

node --import tsx scripts/future-fixes/07.verify.mjs exercises actual capture, CLI rebuild helper, CloseBatch and PayoutBatch: 9775, 9775, 9775, 0. Run against a disposable database because the lifecycle commits fixture rows.

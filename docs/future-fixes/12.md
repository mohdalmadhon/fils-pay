# Audit finding 12: Admin rebuild and worker agree on included backlog

Validated against main `44c2b04`, 2026-10-30. Implemented on `future-fixes`.

## Confirmed problem

The rebuild populates totals from transaction events but originally left the consumer cursor unchanged; a worker then added included captures again.

## Change

The rebuild locks the reporting cursor first, then the outbox in SHARE mode before reading source and writing rollups. It atomically records receipts for visible events and updates freshness. The worker and producers cannot slip a commit between source totals and receipts. Requires migration 0081 from finding 10. This operation can block producers while aggregating; preserve an appropriate admin timeout/maintenance window for large data. Existing historical duplicates require this rebuild after deployment.

## Verification

node --import tsx scripts/future-fixes/12.verify.mjs queues an unconsumed capture, runs the actual admin helper in a transaction, resumes the worker, and asserts exactly one capture total.

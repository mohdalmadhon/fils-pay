# Audit finding 16: Reject future accounting dates before posting credits

Validated against main `44c2b04`, 2026-10-30. Implemented on `future-fixes`.

## Confirmed problem

The input promised today-or-earlier but only validated calendar syntax; a 2099 ledger effective date changed the current cache immediately.

## Change

Validate dates against the Bahrain calendar at request creation and again before posting, including approval of old requests. Bahrain midnight is 21:00Z, so a valid local-today date must not be rejected during the UTC-date overlap. Future legacy requests remain pending until reviewed, not automatically backdated. No migration.

## Verification

node --import tsx scripts/future-fixes/16.verify.mjs checks future rejection and both sides of Bahrain midnight using explicit instants. Existing test files are unchanged.

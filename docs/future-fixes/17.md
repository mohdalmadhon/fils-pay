# Audit finding 17: Go resolves fee schedule corrections in API order

Validated against main `44c2b04`, 2026-10-30. Implemented on `future-fixes`.

## Confirmed problem

Go ordered equal effective dates without created_at, then selected the last row. API orders by effective date and creation time, so an older entry could win in settlement.

## Change

LoadFeeSchedules now sorts effective_from ASC and created_at ASC; its existing reverse traversal selects the latest entry at the latest applicable effective date. No fee formula or historical closed batch is changed.

## Verification

node scripts/future-fixes/17.verify.mjs inserts same-effective-date rates in reverse creation-time order inside a rolled-back Go transaction and asserts Go picks 225, matching the existing API ordering.

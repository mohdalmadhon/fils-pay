# Audit finding 22: Disabling an endpoint pauses queued deliveries

Validated against main `44c2b04`, 2026-10-30. Implemented on `future-fixes`.

## Confirmed problem

Creation filtered active endpoints but the pending-delivery SELECT did not. Previously queued rows continued sending after a disable.

## Change

Due selection now requires an active endpoint, and each row rechecks that state immediately before starting its send. Pending attempts are not spent during pause, and re-enabling resumes the queue. A request already in flight cannot be recalled, and a disable racing the final check may affect the next send; no database transaction is held across HTTP.

## Verification

node --import tsx scripts/future-fixes/22.verify.mjs uses isolated real SQL rows with a stub transport. Disable causes zero sends and no attempts; re-enable sends exactly once. No network call is made.

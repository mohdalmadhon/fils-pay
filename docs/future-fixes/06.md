# Audit finding 06: Discount adjustments identify each capture event

Validated against main `44c2b04`, 2026-10-30. Implemented on `future-fixes`.

## Confirmed problem

The count guard mistakes zero-discount captures for missing credits and reuses the latest event. Multiple partials and replay can credit the same fee repeatedly.

## Change

Capture snapshots its negotiated discount in event metadata. Adjustment locks the owned transaction and each pending capture, then atomically writes its legs and a numeric event marker, including zero. It processes every pending event rather than the latest. Legacy rows without snapshots or with unmapped prior credits stop with legacy_discount_review_required; finance must reconcile them rather than automatic replay.

## Verification

node --import tsx scripts/future-fixes/06.verify.mjs: two captures (zero and 10-fil discounts), initial apply and concurrent replays produce exactly one credit and two completed event markers.

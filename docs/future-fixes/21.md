# Audit finding 21: Deleting a used endpoint retains its audit history

Validated against main `44c2b04`, 2026-10-30. Implemented on `future-fixes`.

## Confirmed problem

The route hard-deletes registrations, but delivery and archive foreign keys were NOT NULL with restrictive deletion, so an endpoint with history returned a foreign-key error.

## Change

Migration 0082 makes both endpoint references nullable with ON DELETE SET NULL, matching the existing delete contract. Bodies, delivery IDs, archive entries and merchant ownership are retained. Queries that join live endpoints naturally stop dispatch/replay for the removed registration; an archive can still be read/restored by its owning merchant onto a new endpoint. No audit rows are cascaded away. Apply migration before relying on deletion.

## Verification

node --import tsx scripts/future-fixes/21.verify.mjs creates a delivery and archive, rejects a foreign-merchant deletion, deletes the owned endpoint through the actual helper and proves history remains readable.

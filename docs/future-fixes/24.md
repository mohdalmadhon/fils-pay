# Audit finding 24: Bulk KYC approves only merchants in the review queue

Validated against main `44c2b04`, 2026-10-30. Implemented on `future-fixes`.

## Confirmed problem

The bulk UPDATE ignored onboarding status, overriding rejected and unreviewed merchants while reporting already-approved ones as newly approved. It also bypassed the canonical per-merchant review trail, though a bulk audit existed.

## Change

Lock only under_review candidates in stable ID order and call recordKycReviewInTx for each. The review, status and bulk admin audit remain one transaction. Concurrent clicks cannot approve the same row twice; skipped IDs are not returned. No historical review records are fabricated.

## Verification

node --import tsx scripts/future-fixes/24.verify.mjs supplies review, approved, rejected and submitted merchants to concurrent bulk calls. Exactly one transition/review is recorded, and rejected/submitted statuses remain intact.

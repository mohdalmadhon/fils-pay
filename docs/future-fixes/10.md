# Audit finding 10: Late commits are consumed independently of sequence IDs

Validated against main `44c2b04`, 2026-10-30. Implemented on `future-fixes`.

## Confirmed problem

An uncommitted event can allocate the lower ID. Processing the higher committed ID and advancing an eligibility watermark permanently skips the late commit.

## Change

Migration 0081 adds per-consumer event receipts. Each receipt, rollup and freshness cursor change is one transaction. Eligibility means no receipt, not ID greater than a watermark. Pause all old worker/catch-up/rebuild processes for migration/deployment; bootstrap receipts preserve existing rollups. Previously missed already-committed historical rows below the old watermark need an explicit reviewed rebuild, whose reset now clears receipts. This is not a claim that timestamps establish commit order.

## Verification

node --import tsx scripts/future-fixes/10.verify.mjs uses actual interleaved PostgreSQL transactions in an isolated schema. The late lower ID is applied after the higher one and a third pass is a no-op.

Keep `ops/.env`, `ops/.env.docker`, the OTP/credential directories, PostgreSQL
and KYC volumes when updating source. Build new images before stopping services;
take a fresh backup before migrations. For a code-only rollback, select prior
image tags in the host override and recreate API/reporting/settlement with
`sudo filspay-compose up -d --no-build --no-deps api reporting settlement`.
Do not restore an old database over newly accepted payments as a code rollback.
Do not run the seed during routine upgrades: it is a deliberate database reset,
requiring explicit authorization and a fresh backup.

## HTTPS certificate (Let's Encrypt)

Later the same day the self-signed certificate was replaced with a Let's
Encrypt certificate for the bare IP, so browsers no longer need explicit
trust. There is no domain; Let's Encrypt issues IP-address certificates only
with the `shortlived` profile, so each certificate is valid for about **6
days**. Renewal is automatic, but a broken renewal shows up as browser
warnings within days, not months. A domain would allow ordinary 90-day
certificates and needs only a DNS A record plus `server_name` changes.

Setup on the host:

- Certbot 5.9 from snap (`/snap/bin/certbot`). Ubuntu's apt certbot 2.9 is
  still installed but cannot issue IP certificates; its `certbot.timer` is
  disabled so only `snap.certbot.renew.timer` renews (twice daily).
- Certificate name `filspay-ip`, files under
  `/etc/letsencrypt/live/filspay-ip/`. Both nginx HTTPS blocks (443 and 8443)
  use `fullchain.pem` and `privkey.pem` from there.
- HTTP-01 validation over port 80 using webroot `/var/www/letsencrypt`. The
  port-80 server in `/etc/nginx/sites-available/filspay` serves
  `/.well-known/acme-challenge/` from that directory and redirects everything
  else to HTTPS. Keep that location and keep port 80 open: renewal depends on
  both.
- Deploy hook `systemctl reload nginx`, stored in
  `/etc/letsencrypt/renewal/filspay-ip.conf`, so nginx picks up each new
  certificate.
- Registered without an email address. Let's Encrypt no longer sends expiry
  emails, so external certificate or uptime monitoring is the only alert.

It was issued with:

```bash
sudo /snap/bin/certbot certonly --non-interactive --agree-tos --register-unsafely-without-email \
  --cert-name filspay-ip --webroot -w /var/www/letsencrypt \
  --ip-address 159.89.173.8 --preferred-profile shortlived \
  --deploy-hook "systemctl reload nginx"
```

Checks:

```bash
# Expiry and issuer of the certificate nginx serves
echo | openssl s_client -connect 159.89.173.8:443 2>/dev/null | openssl x509 -noout -issuer -enddate
systemctl list-timers snap.certbot.renew.timer
sudo /snap/bin/certbot certificates
sudo /snap/bin/certbot renew --dry-run
```

If renewal fails, read `/var/log/letsencrypt/letsencrypt.log`, then check
that `http://159.89.173.8/.well-known/acme-challenge/<file>` is reachable from
outside (port 80 open, the location still in the nginx site), and run
`sudo /snap/bin/certbot renew` by hand.

Rollback: the pre-change site config is
`/etc/nginx/sites-available/filspay.bak-selfsigned-20261030` and the old
self-signed pair is still in `/etc/nginx/filspay-tls/` (valid until
2027-01-28). Copy the backup over the site config, run `sudo nginx -t`, then
`sudo systemctl reload nginx`.

`ops/remote-deploy.sh` runs its own Caddy on ports 80/443 and refuses to
start while nginx holds them; it is not how this host is deployed.

Verified after the switch: strict TLS verification (no `-k`) succeeds on 443
and 8443, `/healthz` returns `ok`, and `certbot renew --dry-run` succeeds.
